# Отзывчивость виджета и меню по ПКМ — проектирование

## Цель

Виджет должен сразу принимать клики после показа рабочего стола. Клик правой кнопкой мыши по любой части виджета должен открывать системное меню с переключателем «Запускать вместе с ПК» и действием «Закрыть».

## Причина задержки

Главный процесс Electron каждые 1,5 секунды читает геометрию значков рабочего стола. Для каждого значка вызывается синхронный Win32 `SendMessageA` в процесс Explorer. Если Explorer занят переключением рабочего стола или временно не обрабатывает сообщения, основной поток виджета ждёт без ограничения времени. В этот период IPC и системное меню не обслуживаются, поэтому действие пользователя выполняется только через несколько секунд.

## Выбранное решение

Вызовы `SendMessageA` выполняются через асинхронный интерфейс Koffi на worker-потоке. Главный event loop Electron продолжает обслуживать клики, IPC и системное меню, даже если Explorer отвечает несколько секунд. Одновременно выполняется не более одного снимка значков, поэтому медленный ответ не создаёт очередь параллельных межпроцессных запросов.

Нативная память Explorer остаётся выделенной до фактического завершения каждого сообщения и освобождается только после callback Koffi. `SendMessageTimeoutA` здесь не используется: возврат по таймауту не отменяет уже переданное сообщение, поэтому немедленное освобождение его выходного буфера было бы небезопасным.

Повторное чтение значков сразу после успешного подключения удаляется: количество уже известно объекту рабочего стола, а второй межпроцессный обход не добавляет достоверности.

После успешного нативного подключения вызывается `showInactive()`. Один `SWP_SHOWWINDOW` делает HWND видимым для Windows, но не переводит созданный с `show: false` `BrowserWindow` в состояние показа внутри Electron, из-за чего прозрачное окно могло оставаться без отрисованной поверхности.

Для ПКМ используется `Menu` Electron в главном процессе. Системное меню не зависит от CSS и отрисовки страницы. Переключатель автозапуска читает фактическое состояние Windows при каждом открытии меню и изменяет его через штатный API Electron с прежним именем записи. Для portable-сборки используется путь внешнего запускаемого файла, а не временно распакованного внутреннего процесса. «Закрыть» вызывает штатное завершение приложения, поэтому существующий механизм восстановления окна не создаёт его заново.

## Отказоустойчивость и проверка

Ошибка нативного вызова или закрытие окна Explorer считаются временной недоступностью: положение не меняется, а следующий плановый цикл повторяет подключение. Тесты фиксируют worker-вызов, безопасное время жизни нативной памяти, сериализацию снимков, установленный и portable-пути автозапуска, фактическое состояние Windows Startup Apps и действие закрытия. Полный набор тестов и сборка должны остаться успешными.
