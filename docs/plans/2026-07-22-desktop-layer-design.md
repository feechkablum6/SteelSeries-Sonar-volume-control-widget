# Виджет на слое рабочего стола — проектирование

## Цель

Виджет должен быть интерактивным элементом рабочего стола Windows: обычные окна перекрывают его естественно, Alt+Tab не вызывает скрытие или мерцание, а ярлыки рабочего стола являются препятствиями при перемещении.

## Архитектура

Окно Electron создаётся скрытым, после загрузки переводится в дочернее окно `Progman` и размещается поверх `SHELLDLL_DefView`. Старые `alwaysOnTop`, 50-миллисекундный опрос перекрытий и вызовы `hide()`/`showInactive()` удаляются. Небольшой сторожевой таймер нужен только для повторного подключения после перезапуска Explorer и обновления геометрии ярлыков; он не меняет видимость окна.

Позиции ярлыков читаются из `SysListView32` через `LVM_GETITEMRECT`. Поскольку список принадлежит процессу Explorer, память для `RECT` выделяется в процессе Explorer и читается через `ReadProcessMemory`. Все координаты приводятся к экранным координатам.

Нативное перетаскивание `-webkit-app-region: drag` заменяется событиями указателя. Главный процесс рассчитывает каждую новую позицию, ограничивает её виртуальным рабочим столом и не разрешает пересечение с прямоугольниками ярлыков. При изменении разрешения, раскладки ярлыков или перезапуске Explorer конфликтующая сохранённая позиция переносится в ближайшее свободное место.

## Отказоустойчивость

Если Explorer временно недоступен, окно остаётся скрытым до появления рабочего стола. Если чтение ярлыков не удалось, движение блокируется в последней подтверждённой позиции, чтобы не допустить сохранения поверх неизвестных препятствий. Все нативные ресурсы процесса Explorer освобождаются после чтения.

## Проверка

Чистая геометрия проверяется модульными тестами: границы экрана, столкновение по каждой оси, скольжение вдоль препятствия и поиск ближайшего свободного места. Затем выполняется ручная проверка на реальном Windows 11: Alt+Tab, Win+D, клики по слайдерам, перемещение возле ярлыков, смена раскладки и перезапуск Explorer.
